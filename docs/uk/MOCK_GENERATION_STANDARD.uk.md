# Стандарт генерації Mock-об'єктів

Цей документ визначає єдиний підхід до генерації mock-об'єктів у всіх модулях проекту Promenade.

## Філософія

**Усі mock-об'єкти ПОВИННІ бути згенеровані за допомогою mockery**, щоб забезпечити:

- Узгодженість у всіх модулях
- Автоматичну синхронізацію зі змінами в interface
- Стандартні інструменти та інтеграцію з CI/CD
- Зменшене навантаження на ручне обслуговування

## Конфігурація

Проект використовує централізований конфігураційний файл `.mockery.yaml` на кореневому рівні, який визначає генерацію mock-об'єктів для:

- Core repositories (`internal/domain/repository`)
- Усіх бізнес-модулів (`internal/modules/*/domain/repository`)

## Встановлення

```bash
make install
# або вручну:
go install github.com/vektra/mockery/v2@latest
```

## Використання

### Генерація всіх Mock-об'єктів

```bash
make mocks
```

Ця команда:

1. Перевіряє, чи встановлено mockery
2. Використовує конфігурацію `.mockery.yaml`
3. Генерує mock-об'єкти для ВСІХ repositories у ВСІХ модулях
4. Розміщує mock-об'єкти в стандартних місцях

### Генерація Mock-об'єктів для конкретного модуля

```bash
make mocks-audit      # Тільки модуль Audit
make mocks-posts      # Тільки модуль Posts
make mocks-profiles   # Тільки модуль Profiles
make mocks-analytics  # Тільки модуль Analytics
```

### Перевірка актуальності Mock-об'єктів

```bash
make mocks-verify
```

Це корисно в CI/CD pipelines для перевірки, що розробники не забули регенерувати mock-об'єкти після змін в interface.

## Стандарт розміщення Mock-об'єктів

Кожен модуль дотримується такої структури:

```
internal/modules/{module_name}/
├── domain/
│   └── repository/
│       ├── {interface_name}.go           # Визначення interface
│       └── mocks/
│           └── {interface_name}_mock.go  # Згенерований mock
```

Для core repositories:

```
internal/
├── domain/
│   └── repository/
│       └── {interface_name}.go           # Визначення interface
└── adapter/
    └── repository/
        └── mocks/
            └── {interface_name}_mock.go  # Згенерований mock
```

## Структура файлу Mock-об'єкта

Усі згеновані mock-об'єкти мають таку структуру:

```go
// Code generated by mockery v2.53.5. DO NOT EDIT.

package mocks

import (
    // imports...
)

// Mock{InterfaceName} is an autogenerated mock type
type Mock{InterfaceName} struct {
    mock.Mock
}

// Interface method implementations...
```

**НІКОЛИ** не редагуйте ці файли вручну. Будь-які зміни будуть перезаписані при наступній генерації.

## Використання Mock-об'єктів у тестах

### Стандартний патерн

```go
package usecase

import (
    "testing"
    "github.com/stretchr/testify/mock"
    "github.com/basilex/promenade/internal/modules/audit/domain/repository/mocks"
)

func TestSomeUseCase(t *testing.T) {
    // Створення mock
    mockRepo := new(mocks.MockAuditEventRepository)

    // Встановлення очікувань
    mockRepo.On("GetByID", mock.Anything, "test-id").Return(expectedEvent, nil)

    // Створення use case з mock
    uc := NewAuditEventUseCase(mockRepo)

    // Тестування
    result, err := uc.GetEvent(ctx, "test-id")

    // Перевірки
    require.NoError(t, err)
    assert.Equal(t, expectedEvent, result)
    mockRepo.AssertExpectations(t)
}
```

## Незалежність модулів

Mock-об'єкти кожного модуля **повністю незалежні**:

- Mock-об'єкти використовують ТІЛЬКИ типи зі свого модуля
- Немає імпортів з `internal/domain` або `internal/usecase`
- Дозволені лише імпорти з `pkg/*`
- Це забезпечує можливість незалежного вмикання/вимикання модулів

## Інтеграція з CI/CD

Додайте до вашого CI pipeline:

```yaml
- name: Verify mocks are up-to-date
  run: make mocks-verify
```

Це гарантує, що розробники регенерують mock-об'єкти при зміні interface.

## Коли регенерувати Mock-об'єкти

Регенеруйте mock-об'єкти, коли ви:

1. Додаєте новий метод до repository interface
2. Змінюєте сигнатури методів (параметри або типи повернення)
3. Додаєте новий repository interface
4. Видаляєте repository interface

## Правила іменування

- **Interface**: `AuditEventRepository`
- **Mock**: `MockAuditEventRepository`
- **Файл**: `audit_event_repository_mock.go`
- **Package**: `mocks`

Усі назви автоматично виводяться mockery з імені interface.

## Міграція з ручних Mock-об'єктів

Якщо у вас є ручні mock-об'єкти (без заголовка "Code generated by mockery"):

1. Зробіть резервну копію ваших тестів, якщо вони покладаються на власну поведінку mock
2. Запустіть `make mocks` для регенерації
3. Оновіть тести для використання стандартних патернів mockery
4. Видаліть ручні реалізації mock

## Вирішення проблем

### Помилка: "mockery not found"

```bash
make install
```

### Помилка: "use of unsupported options detected"

Це попередження можна ігнорувати. Воно з'являється при використанні прапорців командного рядка, які перевизначають налаштування `.mockery.yaml`.

### Тести не проходять після регенерації

Перевірте, що очікування у ваших тестах відповідають фактичним сигнатурам interface. Mockery строго перевіряє типи.

### У Mock-об'єкті відсутній очікуваний метод

Переконайтеся, що interface має цей метод, та регенеруйте:

```bash
make mocks-{module}
```

## Найкращі практики

1. **Ніколи не комітьте ручні mock-об'єкти** - Завжди використовуйте згеновані mockery
2. **Регенеруйте після змін interface** - Не забувайте запускати `make mocks`
3. **Використовуйте `mock.Anything` для контекстів** - Якщо тільки не тестуєте специфічну поведінку контексту
4. **Перевіряйте очікування** - Завжди викликайте `mockRepo.AssertExpectations(t)` наприкінці тестів
5. **Тримайте mock-об'єкти простими** - Складна поведінка вказує на те, що interface може бути занадто широким

## Підсумок

✅ **РОБІТЬ**:

- Використовуйте mockery для ВСІЄЇ генерації mock-об'єктів
- Запускайте `make mocks` після змін interface
- Використовуйте стандартні патерни mock у тестах
- Підтримуйте незалежність модулів

❌ **НЕ РОБІТЬ**:

- Не редагуйте згеновані файли mock вручну
- Не створюйте ручні реалізації mock
- Не імпортуйте core packages у mock модулів
- Не комітьте застарілі mock-об'єкти, які не відповідають interface

**Дотримання**: Цей стандарт є обов'язковим для всіх модулів. Усі існуючі ручні mock-об'єкти повинні бути мігровані на згеновані mockery.
