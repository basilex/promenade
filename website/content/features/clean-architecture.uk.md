## Чиста Архітектура

Promenade дотримується принципів **Чистої Архітектури дядька Боба** зі строгими правилами залежностей та чіткими межами шарів.

### Чотири Шари

```
Domain (сутності, інтерфейси)
    ↓
Use Case (бізнес-логіка)
    ↓
Adapter (репозиторії, обробники)
    ↓
Infrastructure (БД, HTTP, події)
```

### Правило Залежностей

**Внутрішні шари ніколи не залежать від зовнішніх**. Це забезпечує:

- Бізнес-логіка не залежить від фреймворків
- Легке тестування з mock-реалізаціями
- Гнучка зміна інфраструктури
- Чіткі межі між компонентами

### Приклад Структури

```go
// Domain шар - чисті бізнес-сутності
type User struct {
    ID        uuid.UUID
    Email     string
    Status    UserStatus
}

// Use case - тільки бізнес-логіка
type UserUseCase interface {
    RegisterUser(ctx, email, password) (*User, error)
}

// Adapter - інтеграція з фреймворком
type UserHandler struct {
    usecase UserUseCase
}

func (h *UserHandler) Register(c *gin.Context) {
    // HTTP-специфічний код тут
}
```

### Переваги

✅ **Тестовність** - Mock будь-якого шару незалежно  
✅ **Підтримуваність** - Зміни ізольовані в одному шарі  
✅ **Масштабованість** - Додавайте функції без поломки коду  
✅ **Незалежність від фреймворків** - Бізнес-логіка не знає про HTTP чи БД
